## 二、用户痛点

| 编号 | 痛点 | 现有方案的不足 | 本项目的解决思路 |
|---|---|---|---|
| **P1** | **AI 对话内容易流失** | ChatGPT / Claude 对话内容散落，下次想找找不到 | 闪念速记一键沉淀 + 全文搜索 + 标签 |
| **P2** | **复制粘贴繁琐，懒得记** | 切换笔记软件复制粘贴的"仪式感"让人放弃 | 闪念速记（Ctrl+Shift+N）+ 一句话记录 |
| **P3** | **笔记与 AI 上下文割裂** | 笔记软件不知道 AI 在聊什么，AI 也不知道笔记里有什么 | AI 上下文调用（笔记作为 RAG 上下文） |
| **P4** | **复习无抓手** | 记了一堆笔记，复习时没有 AI 引导 | AI 评论 + AI 总结 + AI 复习（自动出题） |

> 填写提示：每条痛点要能对应到一个功能，否则就是凑数。建议 3~4 条，用真实观察或访谈支撑。

## 三、产品定位

面向大学生与自学者群体的 **AI 驱动学习笔记平台**：

> **主要功能**：笔记 / 闪念的创建与管理。  
> **亮点功能**：AI 在笔记入库后提供**评论 / 查找 / 调用**三种能力，让每一条记录都能被复习、被检索、被对话。

**一句话定义**：在课堂、自学或 AI 对话中获得灵感 → 一键「闪念 / 笔记」沉淀 → AI 自动评论 + 智能查找 + 上下文调用 → 形成"记 → 评 → 找 → 用"的学习闭环。

**差异化对比**

| 对比项 | Notion / 印象笔记 | ChatGPT / Claude | **AI智能笔记（本项目）** |
|---|---|---|---|
| 笔记 / 闪念 | ✅ 手动为主 | ❌ 无 | ✅ 一等公民，Ctrl+Shift+N 全局快捷键 |
| AI 评论 | ❌ 弱或无 | ❌ 无 | ✅ 保存即自动评论（亮点①） |
| AI 查找 | ⚠️ 关键词搜索 | ❌ 对话历史难找 | ✅ 全文搜索 + AI 摘要 Top-N（亮点②） |
| AI 调用 | ❌ 无 | ✅ 但上下文割裂 | ✅ 以笔记为 RAG 上下文（亮点③） |
| 知识沉淀 | 手动归档 | 无沉淀 | 自动入知识库 + 可复习 |
| 复习闭环 | 无 | 无 | AI 总结 + AI 复习（自动出题） |
| 适用场景 | 个人整理 | AI 助理 | 学习闭环 |

## 四、核心功能

| 编号 | 功能模块 | 功能说明 | 优先级 |
|---|---|---|---|
| 1 | **用户系统** | 注册 / 登录 / 登出 + Session 鉴权 + 数据隔离 | P0 |
| 2 | **笔记管理** | 笔记 CRUD + Markdown 渲染 + 标签 + 全文搜索 | P0 |
| 3 | **闪念速记** | Ctrl/Cmd+Shift+N 全局快捷键，一句话记录，type=1 | P0 |
| 4 | **AI 评论**（亮点①） | 保存笔记后异步调用 gpt-4o-mini 生成 1-2 条评论（补充 / 提问 / 扩展） | P0 |
| 5 | **AI 智能查找**（亮点②） | 全文搜索 + 标签筛选 + AI 摘要 Top-N 二次召回 | P0 |
| 6 | **AI 上下文调用**（亮点③） | 以笔记 / 闪念为 RAG 上下文，支持 AI 对话 / 总结 / 复习 | P1 |
| 7 | **AI 对话** | 多轮对话 + 流式输出 + 历史持久化（作为 AI 调用的入口之一） | P1 |
| 8 | **用户管理 / 标签** | 个人资料、密码修改、用户私有标签管理 | P1 |
| 9 | **双向追溯** | 笔记 ↔ 对话（Message.savedAsNoteId） | P2 |
| 10 | **暗色模式** | 浅 / 深主题切换 | P2 |

## 五、技术难点

| 编号 | 技术难点 | 为什么难 | 应对方案 | 负责人 |
|---|---|---|---|---|
| 1 | **闪念速记的全局快捷键** | 浏览器安全策略下 Ctrl+Shift+N 易与系统/扩展冲突 | 浏览器扩展（Manifest V3）+ 前端键盘事件兜底；冲突时提示用户修改 | 前端工程师 |
| 2 | **流式 AI 对话 + 笔记入库** | SSE 流式输出过程中如何保存完整消息，并支持"选中片段"操作 | OpenAI SDK 流式 API + 前端 EventSource；完成后批量入库 Message 表 | 后端工程师 |
| 3 | **AI 评论的异步与降级** | 保存不能被 AI 阻塞；AI 失败时不能影响主流程 | 入库后立即返回 noteId；评论走异步任务（pg-boss / 内存队列），超时 10s 放弃 + 失败重试 1 次 | 后端工程师 |
| 4 | **AI 上下文调用（RAG）** | 长笔记超出 token 限制 + 多笔记组合的相关度排序 | 笔记内容摘要预计算 + Top-K 检索（向量 or 关键词）+ 上下文截断到 4k token | 后端工程师 + 架构师 |
| 5 | **Markdown 渲染与 XSS** | 笔记内容含用户输入，AI prompt 注入风险 | 白名单过滤（仅允许 h1-h6 / p / ul / ol / li / code / pre / blockquote / a / strong / em / img）；图片仅允许站内白名单域名 | 前端工程师 |
| 6 | **全文搜索性能** | 1000+ 笔记下 LIKE 模糊查询拖慢列表 | SQLite FTS5（开发） / PostgreSQL `to_tsvector` + GIN 索引（生产）；标签筛选走索引 | 后端工程师 |
| 7 | **AI API 成本控制** | 高频调用导致 token 费用超支 | gpt-4o-mini + 上下文截断 + 重复请求缓存（Redis / 内存 LRU）+ 评论降级为占位 | 后端工程师 |

> 填写提示：难点必须是真实的技术问题，"时间紧""需求变"这类管理问题不写在这里。每条都要有应对方案，否则等于承认做不出来。
